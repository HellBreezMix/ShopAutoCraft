# Автокрафт магазина — установка с нуля

Локальная система автокрафта для OpenComputers + Applied Energistics 2, без своего сервера и без ежемесячной платы. Уведомления и управление — через Discord, бесплатный "мост" — Cloudflare Worker.

## Что это умеет

- Следит за складом в ME-сети, докрафчивает то, что упало ниже порога
- Шлёт уведомления в Discord (на каждый тик и/или раз в сутки сводкой)
- Управляется прямо командами в Discord-канале (пауза, статус, список товаров, изменение порогов и т.д.)
- Есть простая веб-страница со статусом (открывается в браузере, обновляется сама)
- Сигнализирует, если компьютер завис/перезагрузился и не выходит на связь
- В игре — свой графический интерфейс с тачскрином: список активных крафтов, добавление/редактирование/удаление товаров через сканирование сундука

Ничего из этого не требует своего VPS/хостинга — вся "облачная" часть держится на бесплатных лимитах GitHub и Cloudflare.

---

## Архитектура (коротко)

```
Компьютер в игре (OpenComputers)
     │
     │  HTTP (Internet Card)
     ▼
Cloudflare Worker  ──────────────►  Discord (вебхук — уведомления)
     │         ▲                    Discord Bot API (чтение команд из канала)
     │         │
     ▼         │
 KV-хранилище (статус для веб-страницы, "жив ли компьютер")
     │
     ▼
Веб-страница (тот же Worker отдаёт HTML на GET-запрос из браузера)
```

Компьютер в игре ничего не хранит "в облаке", кроме периодического снимка статуса. Все настройки (список товаров, пороги) — локальный файл на самом компьютере.

---

## Что понадобится

**В игре:**
- Компьютер OpenComputers (Case, желательно не самый маленький — минимум пара плашек RAM)
- Internet Card
- Экран + Тачскрин + GPU (для интерфейса)
- Клавиатура (для ввода текста при добавлении товаров)
- Adapter, подключённый к ME Interface вашей AE2-сети
- Обычный сундук рядом с (отдельным) Adapter'ом — для сканирования новых товаров. В зависимости от сборки мода это либо:
  - Adapter с вставленным апгрейдом **Inventory Controller Upgrade**, либо
  - Некоторые сборки дают доступ к обычному сундуку через Adapter напрямую, без апгрейда (тогда сундук появится в списке компонентов сразу под именем `chest`)

**Аккаунты (все бесплатные):**
- GitHub — https://github.com/signup
- Discord (у вас наверняка уже есть)
- Cloudflare — https://dash.cloudflare.com/sign-up

## Шаг 1. GitHub — репозиторий с файлами

1. Зайдите на https://github.com/new
2. Название — например `oc-crafter`
3. Обязательно **Public** (иначе OC не сможет скачать файлы без авторизации)
4. Create repository

Загрузите в него следующие файлы (Add file → Upload files):

| Файл | Назначение |
|---|---|
| `config.lua` | Настройки — интервалы, флаги |
| `network.lua` | Не используется активно (локальный режим), но нужен по зависимостям |
| `json.lua` | JSON-кодирование/декодирование |
| `gui.lua` | Интерфейс на экране в игре |
| `crafter.lua` | Основная логика автокрафта |
| `discord.lua` | Отправка уведомлений в Discord |
| `commands.lua` | Приём команд из Discord |
| `crafter_data.json` | Список товаров (пример на старте) |
| `installer.lua` | Установщик — скачивает всё остальное |

Файл `secret.lua` **не загружайте с реальными данными** — вместо него залейте шаблон:
```lua
-- /home/secret.lua
return {
    discord_webhook_url = "",
}
```
Реальное значение впишете позже прямо в игре — это личные данные, им не место в публичном репозитории.

Отдельно залейте **`worker.js`** — этот файл `installer.lua` не скачивает (он никогда не попадает в игру), он нужен только как копия кода для Cloudflare Worker в шаге 4.

В `installer.lua` замените строку с адресом репозитория на свою:
```lua
local repo = "https://raw.githubusercontent.com/ВАШ_НИК/oc-crafter/main/"
```

## Шаг 2. Discord — вебхук для уведомлений

1. На вашем Discord-сервере: канал → значок шестерёнки → **Интеграции → Вебхуки → Создать вебхук**
2. Скопируйте **URL вебхука** (понадобится позже, но не сюда, а в `secret.lua` в игре)

---

## Шаг 3. Discord — бот для удалённого управления

1. https://discord.com/developers/applications → **New Application** → дайте имя
2. Вкладка **Bot** → **Reset Token** → скопируйте токен (показывается один раз!)
3. Там же включите **MESSAGE CONTENT INTENT** (в разделе Privileged Gateway Intents)
4. Вкладка **OAuth2 → URL Generator** → Scopes: `bot` → Permissions: `View Channels`, `Read Message History` → скопируйте получившуюся ссылку, откройте в браузере, пригласите бота на свой сервер
5. В Discord: правый клик по каналу, где будут уведомления → **Копировать ID** (если пункта нет — включите в настройках Discord "Режим разработчика")

Держите под рукой: **токен бота** и **ID канала**.

## Шаг 4. Cloudflare Worker

### 4.1 Создание

1. https://dash.cloudflare.com → **Workers & Pages → Create → Create Worker → Start with Hello World!**
2. Дайте имя (например `my-crafter-relay`) → Deploy
3. **Edit code** → вставьте содержимое `worker.js` (из репозитория/файлов ниже) → **Deploy**

### 4.2 Секреты

**Settings → Variables and secrets → Add variable**, четыре штуки:

| Имя | Тип | Значение |
|---|---|---|
| `DISCORD_WEBHOOK_URL` | Secret | ссылка вебхука из шага 2 |
| `DISCORD_BOT_TOKEN` | Secret | токен бота из шага 3 |
| `DISCORD_CHANNEL_ID` | Text | ID канала из шага 3 |

После добавления — **Deploy**.

### 4.3 KV-хранилище (для веб-страницы и "мёртвого счётчика")

1. **Storage & Databases → KV → Create a namespace**, имя например `crafter-state` → Create
2. Вернуться в Worker → **Settings → Bindings → Add binding → KV Namespace**
3. Variable name: **строго `STATE`** (так называется в коде) → выбрать `crafter-state` → Save → Deploy

### 4.4 Cron Trigger (сигнал "крафтер не отвечает")

**Settings → Trigger Events → Cron Triggers → Add Cron Trigger**
Расписание: `*/5 * * * *` (каждые 5 минут) → Save.

### 4.5 Проверка

Откройте адрес вашего Worker'а в браузере (`https://ИМЯ.ВАШ_АККАУНТ.workers.dev`) — должна открыться страница "Ожидание первых данных..." (это нормально, компьютер в игре ещё не подключался).

## Шаг 5. Железо в игре

1. Соберите компьютер: Case + CPU + RAM (несколько плашек) + Screen + GPU + Touchscreen + Keyboard + Internet Card
2. Adapter → соедините кабелем с компьютером, приставьте к ME Interface вашей AE2-сети
3. Отдельный сундук рядом со вторым Adapter'ом (или второй гранью того же) — для сканирования товаров. Если ваша сборка требует апгрейд — вставьте **Inventory Controller Upgrade** в этот Adapter

## Шаг 6. Установка программы

В консоли компьютера (наберите `wget` — если команда не найдена, установите: `opm install wget`):

```
wget -f https://raw.githubusercontent.com/ВАШ_НИК/oc-crafter/main/installer.lua /home/installer.lua
installer
```

Дальше:
```
edit /home/secret.lua
```
Впишите настоящую ссылку вебхука из шага 2:
```lua
return {
    discord_webhook_url = "https://ИМЯ.ВАШ_АККАУНТ.workers.dev",
}
```
**Важно**: сюда идёт адрес вашего **Worker'а**, а не прямая ссылка Discord — весь трафик идёт через него.

Сохраните (`Ctrl+S`, `Ctrl+W`).

### Автозапуск (по желанию)

```
edit /home/.shrc
```
Впишите одну строку:
```
crafter
```
Сохраните. Теперь программа будет стартовать сама при каждой загрузке компьютера.

## Шаг 7. Запуск и первая проверка

```
crafter
```

В статусной строке должно быть `ME: OK`. В Discord должно прийти сообщение `[СТАРТ] ...`.

Напишите в Discord-канал:
```
!help
```
Через 10-20 секунд бот должен ответить списком команд.

## Шаг 8. Добавление товаров

**Через игру:** на главном экране кнопка **[+ ДОБАВИТЬ ТОВАР]** → положите предмет в сундук → **[СКАНИРОВАТЬ СУНДУК]** → задайте название/количества → **[СОХРАНИТЬ]**.

```

```

## Справочник команд Discord

| Команда | Что делает |
|---|---|
| `!статус` | Текущее состояние + ссылка на веб-страницу |
| `!товары` | Список товаров с реальными остатками |
| `!найти <часть названия>` | Поиск предмета по всей ME-сети (узнать id) |
| `!добавить <id> <damage> <крафт> <порог> <название>` | Добавить/обновить товар |
| `!порог N значение` | Изменить порог у товара №N (номер из `!товары`) |
| `!крафт N значение` | Изменить размер партии крафта у товара №N |
| `!вкл N` / `!выкл N` | Включить/выключить товар №N |
| `!пауза` / `!авто` | Приостановить/возобновить автокрафт |
| `!тик` | Принудительный тик прямо сейчас |
| `!лимит N` | Сменить лимит одновременных крафтов |
| `!help` | Этот список |

## Настройки config.lua

```lua
crafter_interval               = 300,    -- интервал полного тика, сек
crafter_max_concurrent         = 6,      -- сколько крафтов одновременно
crafter_amount                 = 64,     -- крафт по умолчанию для новых товаров
crafter_log_jobs               = false,  -- true — уведомление на КАЖДЫЙ отдельный крафт
crafter_notify_every_tick      = true,   -- false — отключить сообщение на каждый тик
crafter_daily_summary_interval = 86400,  -- сводка раз в сутки (в секундах)
```

## Известные особенности (чтобы не наступать на те же грабли)

1. **После обновления файлов через `wget` — делайте `reboot`.** OpenOS кэширует уже загруженные модули (`require`) в памяти на весь сеанс; без перезагрузки новый код может не примениться, хотя файл на диске уже новый.

2. **Discord API блокирует прямые запросы от OC без заголовка `User-Agent`.** В `discord.lua` и `commands.lua` он уже прописан — если пишете что-то своё поверх, не забывайте про этот заголовок, иначе Cloudflare отдаст 403.

3. **Cloudflare может по-разному относиться к `GET` и `POST` от Java-клиента OC.** Поэтому весь обмен между игрой и Worker'ом в этой системе идёт через `POST` (даже опрос команд) — Worker сам разбирает, что именно просят, по содержимому JSON в теле запроса.

4. **"Холодный старт" опроса команд не читает всю историю канала.** Discord API с `after=0` отдаёт самые **старые** сообщения, а не последние — поэтому при первом запуске Worker вместо этого просто запоминает текущий момент как точку отсчёта и слушает только то, что появится после.

5. **RAM у компьютера ограничена.** Встроена защита: при 70% занятой памяти — предупреждение, при 82% — автосброс внутренних кэшей, при 92% — принудительная перезагрузка компьютера (с последующим автостартом через `.shrc`, если он настроен).

6. **Файлы `config.lua`, `secret.lua` и `crafter_data.json` защищены** от перезаписи при повторном запуске `installer` — там ваши личные настройки. Обновляются только программные файлы.
